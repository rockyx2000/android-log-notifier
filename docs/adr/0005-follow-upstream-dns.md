# 0005. 上流 DNS をネットワークの変化に追従させる

- 状態: 採用
- 日付: 2026-10-07

## 背景

当初は、VPN の確立前に 1 回だけ上流 DNS を取得していた。そのため、スリープ明けなどに Wi-Fi とモバイル回線が切り替わると、古い DNS へ転送し続けて、名前解決に失敗する可能性があった。

また、VPN の確立後は `activeNetwork` が VPN 自身(DNS は `10.0.0.1`)を指しうる。そのまま取得すると、自分宛てに転送するループになる。

## 決定

- 上流 DNS を `@Volatile` なフィールドにし、問い合わせごとに最新の値を読む。
- `registerNetworkCallback`(`INTERNET` かつ `NOT_VPN`)で、接続・DNS の変更・切断を監視し、そのたびに更新する。コールバックは、サービスの停止時と破棄時に解除する。
- 上流 DNS を探すときは、**VPN を除外** し、`INTERNET` を持つネットワークから、IPv4 の DNS を選ぶ。見つからなければ `8.8.8.8` を使う。

## 結果

得たもの

- ネットワークが切り替わっても、名前解決が止まらない。
- VPN 自身を上流として選ぶ事故を防げる。

失ったもの

- エミュレーターでは、DNS が常に `10.0.2.3` で変わらない。「DNS が別の値に変わる」ケースは、実機で確かめる必要がある(エミュレーターでは、Wi-Fi のオフ / オンの後に名前解決と記録が続くところまで確認した)。
- 上流が複数あっても、IPv4 の先頭の 1 つだけを使う。

## 検討した代替案

- **`registerDefaultNetworkCallback`**: VPN 確立後は、既定のネットワークが VPN になるので、除外の処理が別途必要になる。
- **問い合わせごとに毎回取得する**: 呼び出しが多く、無駄が大きい。
