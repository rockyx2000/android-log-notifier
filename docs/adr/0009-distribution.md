# 0009. 配布方法: パッケージ名・署名・最小 OS・ライセンス

- 状態: 採用
- 日付: 2026-10-07

## 背景

開発中は Debug ビルドをエミュレーターに入れていたが、実機(Nothing Phone)へ入れる APK を作る段階になった。
この時点で、後から変えにくいもの(パッケージ名・署名鍵・最小 OS)と、公開の条件(ライセンス)を決める必要があった。

## 決定

- **パッケージ名**: `com.example.dnslogger`(仮の名前)から `com.github.rockyx2000.dnslogger` へ変更する。GitHub のユーザー名に基づき、他と衝突しにくい。`namespace`、ソースのパッケージ、ブロードキャストの action 名も合わせて変えた。インストールが 1 回もない段階だったので、データの移行は不要だった。
- **署名**: リリース APK は、自分で作った鍵(RSA 4096 bit・有効期間約 27 年)で署名する。鍵とパスワードは、リポジトリの外に置く。`keystore.properties`、`*.jks`、`*.keystore` は `.gitignore` に入れる。`keystore.properties` が無いときは、署名なしの APK になる(誤って別の鍵で署名しないため)。
- **縮小**: リリースでは R8 によるコードの縮小・難読化と、リソースの縮小を有効にする。マニフェストに宣言したコンポーネントは自動で保持されるので、追加の規則は不要だった。リリースビルドで、VPN の起動、DNS の記録、画面表示が動くことを確認した。
- **最小 OS を Android 12(API 31)にする**: 当初は API 26 だったが、リントで、API 29〜31 以降のメソッド(`startForeground` の 3 引数版、`WindowInsets.getInsets`、`canScheduleExactAlarms`)が、古い端末でクラッシュすることが分かった。対象機種の Nothing Phone は Android 12 以降なので、古い端末向けの分岐は書かず、最小 OS を上げて解決した。通知の許可だけは、Android 12 に存在しない概念なので、判定を分岐させた。
- **バックアップ**: `allowBackup=false` に加え、Android 12 以降の `dataExtractionRules` で、クラウドバックアップと端末間の移行から、設定(Webhook URL)とログを除外する。
- **アイコン**: アダプティブアイコン(虫眼鏡の中に `>_`)を、ベクターで用意する。テーマアイコン用の monochrome も含む。
- **ライセンス**: **MIT**。個人ツールを公開する際の標準的な選択で、再利用を妨げない。

## 結果

得たもの

- 実機へ入れられる、署名つきの小さな APK(約 90 KB)ができる。
- 古い OS 向けの、確認できない分岐を持たずに済む。

失ったもの

- Android 11 以前の端末では動かない。
- 署名鍵を失うと、同じアプリとして更新できない。鍵のバックアップは、利用者の責任になる。
- Play ストアでの配布は想定していない。`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` は、ストアの審査で問題になりうる([0004](0004-foreground-service-and-power.md))。
- MIT なので、第三者が改変して再配布することを、止められない。

## 検討した代替案

- **最小 OS を 26 のまま、各 API に分岐を入れる**: 古い端末を試せないまま、コードだけが増える。
- **Debug の鍵で配る**: 手軽だが、Debug 用の鍵は共有されやすく、更新の継続性も保証されない。
- **GPL-3.0**: 改変版にも公開を求められるが、個人ツールには過剰と判断した。
