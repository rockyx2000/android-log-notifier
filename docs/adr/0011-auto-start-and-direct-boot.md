# 0011. 開いたら自動で開始し、ロック解除前の再起動でも回復する

- 状態: 採用
- 日付: 2026-10-08

## 背景

v1.1 の挙動には、2 つの手間があった。

1. 初回は「開始」を押し、VPN の許可ダイアログを自分で出す必要があった。止まっていても、アプリを開き直すと自動で再開するのは、「開始」を押した後だけだった。
2. 端末を再起動すると、**最初にロックを解除するまで** 記録が再開しなかった。保存データを、ロック解除後にしか読めない領域(CE)に置いていたためである(エミュレーターで PIN を設定して確認した)。再起動から解除までの間は、何も記録されない。

「見守りの用途で、気づかないうちに止まっている」のは避けたい([0006](0006-detect-and-report-gaps.md))。

## 決定

### 1. 開いたら自動で開始する

- アプリを開いたとき、止まっていて、`auto_start` が真なら、自動で開始する。新規インストールでは `auto_start` は真である。
- ダイアログが重ならないよう、**1 つずつ順に** 出す: 通知の許可 → バッテリー最適化の除外 → VPN の許可と開始。各ダイアログを閉じるたびに、次へ進む。通知を断られても、記録は動く(先へ進む)。
- `auto_start` は、次の場合に **偽** にする。「開始」を押せば真に戻る。
  - ユーザーが「停止」を押した(アプリのボタンでも、通知の「停止」でも)。
  - VPN の許可ダイアログで、断った。
  - 他の VPN アプリに奪われて、OS に解除された。**他の VPN を黙って奪い返さない** ためである。
- 更新前の利用者は、更新前の `enabled`(開始状態だったか)を、`auto_start` に引き継ぐ。

### 2. ロック解除前の再起動でも回復する(Direct Boot)

- `BootReceiver` と `DnsVpnService` を `directBootAware` にし、`LOCKED_BOOT_COMPLETED`(起動直後・ロック解除前)でも VPN を再開する。
- **ロック解除前から要る最小限の状態だけを、端末保護ストレージ(DE)に置く。**

  | 内容 | 置き場所 | 理由 |
  | --- | --- | --- |
  | 動作状態(`enabled`・`auto_start`)、生存確認、途切れの記録 | **DE** | 再開の判断と、途切れの検知に要る。時刻と真偽値だけ |
  | 記録対象のドメイン | **DE** | ロック中も、記録の対象を判定するのに要る |
  | Webhook URL、送信の状態、最後に送った時刻 | CE | ロック解除前は不要で、**秘密情報**なので、守る |
  | アクセスログ | CE | 閲覧の記録なので、守る |

- ロック中の記録は、**DE の一時バッファ** に書く(上限 1 MB)。ロック解除後(`BOOT_COMPLETED`、またはアプリを開いたとき、または次の追記)に、CE のログへ取り込み、バッファを消す。
- ロック中は、集計の送信を行わない(Webhook とログを読めない)。解除後の `BOOT_COMPLETED` で、送信漏れを補完する。この補完と、サービス開始時の補完が重なっても、二重に送らないよう、排他制御する。
- 更新前に CE に置いていた状態は、ロックを解除した後(アプリを開いたとき、または `BOOT_COMPLETED`)に、DE へ移す。DE に無い項目だけを補い、DE の新しい値は壊さない。

## 結果

得たもの

- 初回の操作が減る。以後は、アプリを開くだけで始まる。
- 電源を入れた直後から記録が再開する。再起動から解除までの空白がない。
- エミュレーターで確かめた(PIN を設定した状態の再起動)。解除前に VPN が回復し、ロック中の記録が、解除後にログへ取り込まれた。対象外のドメインは、ロック中も記録されない。

失ったもの(**プライバシー上のトレードオフ**)

- **記録対象のドメインの一覧が、ロック解除前から読める領域に置かれる。** この領域は、端末の起動後であれば、ユーザーの PIN がなくても読める(OS の鍵で暗号化されている)。端末を起動直後の状態で押収された場合などに、一覧が読まれうる。
- **ロック中の記録(最大 1 MB)も、同じ領域に一時的に置かれる。** 解除後は、CE へ移して消す。
- 他の保存データ(Webhook URL、アクセスログ)は、従来どおり CE に置く。ログの大部分は、守られたままである。
- この方針は、[0002](0002-minimize-collected-data.md) の「記録を最小にする」の範囲内で、**保存場所の保護の強さを一部下げる** 決定である。許容できない場合は、ロック解除前の回復を、無効にする選択もありうる(その場合は、`directBootAware` を外し、状態を CE に戻す)。

## 検討した代替案

- **自動開始を、常に行う(停止した後も)**: 「停止」の意味がなくなる。ユーザーが意図して止めたものを、次に開くだけで戻すのは、不意打ちになる。
- **他の VPN に奪われた後も、開いたら奪い返す**: 利用者が意図して使っている VPN を、黙って止めてしまう。
- **ロック解除前の記録を、すべて破棄する**: 実装は単純だが、再起動から解除までの記録が、確実に欠ける。
- **すべての状態とログを DE に置く**: 実装は最も簡単だが、Webhook URL とアクセスログの保護が下がる。必要最小限だけを移す方式にした。
