# 0002. 記録するデータを最小にする(指定 FQDN のみ・端末内保存)

- 状態: 採用
- 日付: 2026-10-07

## 背景

DNS の問い合わせ履歴は、そのまま閲覧履歴に近い機微な情報になる。
必要以上に集めたり、端末の外へ出したりしないことを、設計の前提にしたい。

## 決定

- **指定した FQDN に一致する問い合わせだけを保存する。** 一致しないものは転送するだけで記録しない。リストが空なら何も記録しない。
- 指定の書式は、サフィックス一致(`dmm.co.jp` → サブドメインも対象)と完全一致(`=www.dmm.co.jp`)の 2 つにする。設定は次のクエリから反映する。
- ログは端末の内部ストレージ(`filesDir`)に、`時刻 / FQDN / 種別` の TSV で追記する。
- 同一 FQDN は 60 秒以内なら 1 回とみなす。A / AAAA / HTTPS が続けて来るためである。
- ログは 5 MB でローテーションし、1 世代だけ保持する。
- 端末の外へ出すのは、毎日の集計(FQDN ごとの回数と最終時刻)だけにする(→ [0003](0003-daily-summary-via-discord.md))。
- `allowBackup=false` として、バックアップ経由での持ち出しも防ぐ。

## 結果

得たもの

- 保存される情報が、本人が指定した範囲に限られる。端末を紛失しても、見られる履歴は限定的である。
- ログが際限なく増えない。

失ったもの

- 指定していないドメインの履歴は、後から遡れない。
- 重複の抑制と、キャッシュにより、回数は実際の閲覧回数より少なくなる。「何回見たか」ではなく「その日に接触があったか」を見る用途に向く。

## 検討した代替案

- **すべて記録して、表示時に絞り込む**: 後から条件を変えられるが、不要な履歴まで残してしまう。
- **ログを暗号化する**: 端末内の保存なので、今回は見送った。必要になれば別の ADR で扱う。
