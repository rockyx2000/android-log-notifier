# 0004. フォアグラウンドサービスで常駐し、省電力の除外を案内する

- 状態: 採用
- 日付: 2026-10-07

## 背景

DNS の記録は、端末が起きている間は止まらず動き続ける必要がある。
一方、Android は省電力のためにバックグラウンドのプロセスを止める。特にメーカー独自の最適化は強い。
利用者に「スリープした後も動くか」と問われる場面が、実際にあった。

## 決定

- `VpnService` をフォアグラウンドサービス(種別 `systemExempted`)として動かし、常駐の通知を出す。通知から「停止」できる。
- `START_STICKY` で、終了させられても再起動を試みる。ただし、これに頼らない(次項)。
- `BootReceiver` で、端末の再起動後とアプリ更新後に再開する。ユーザーが明示的に停止した場合は、再開しない(`enabled` フラグ)。VPN の許可が取り消されている場合は、画面なしでは再開できないので、何もしない。
- アプリを開いたときに、「開始」のまま止まっていれば再開する。エミュレーターで、`kill -9` した後に自動では復帰しなかったため。
- **バッテリー最適化の除外** を、起動時に 1 回だけ標準ダイアログで案内する。画面には、除外の状態と「正確なアラーム」の状態を表示し、タップで該当の設定へ移動できる。
- Nothing Phone など実機向けに、標準の除外だけでは足りない設定(アプリごとのバッテリー使用量を「制限なし」、アプリのロック、バッテリーセーバーのオフ)を README に書く。

> **追記(2026-10-08)**: 再起動後の再開は、ロック解除前(`LOCKED_BOOT_COMPLETED`)にも行うようになった。アプリを開いたときの自動開始も、初回から行う。[0011](0011-auto-start-and-direct-boot.md) を参照。

## 結果

得たもの

- 画面オフやロック中も、記録は動き続ける。23:00 のアラームは Doze 中でも発火する。
- 止められた場合も、再起動、アプリ更新、アプリを開いたときの 3 つの契機で復帰する。

失ったもの

- 常駐通知が出続ける。
- `START_STICKY` の再起動は OS 任せで、確実ではない。メーカー独自の制限は、アプリ側では完全に防げない。→ 止まったことを検知する仕組みで補う([0006](0006-detect-and-report-gaps.md))。
- `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` は、ストアの審査で説明を求められることがある。個人利用での配布を想定している。

## 検討した代替案

- **`WorkManager` / `JobScheduler`**: バックグラウンドの制約を受け、VPN の常駐には使えない。
- **`WakeLock` を常時保持する**: 電池の消費が大きく、OS からの制限も受ける。今回は見送った。
