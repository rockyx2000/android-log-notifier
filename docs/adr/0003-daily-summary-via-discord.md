# 0003. 毎日 23:00 に Discord Webhook へ集計を送る

- 状態: 採用
- 日付: 2026-10-07

## 背景

記録を、本人以外が確認できる形で受け取りたい。専用のサーバーやアカウント基盤は作りたくない。
毎日決まった時刻に届き、送れなかった分は後から必ず補われる必要がある。

## 決定

- 送信先は **Discord の Webhook** にする。サーバー不要で、通知がそのまま届く。
- 区切りは端末のローカル時間の **23:00**。`AlarmManager.setExactAndAllowWhileIdle` で登録する。Doze 中でも発火する。
- 「正確なアラーム」が未許可の場合は `setAndAllowWhileIdle` に落とす。数分〜数十分ずれることがある。保存時に、設定画面へ誘導する。
- 集計の範囲は、**前回送信済みの終端 `lastEnd` から直近の 23:00 まで** とする。送信できなかった期間も、次回の集計に含まれる。
- 送信に失敗したら、`lastEnd` を進めずに 15 分後に再試行する。
- 初回は、直近の 23:00 を起点に登録するだけで、空のサマリは送らない。
- 本文は Discord の上限 2000 文字に収める。収まらない分は「…他 N ドメイン」と省略する。
- Release ビルドでは `https://` の Webhook URL だけ受け付ける。Debug ビルドに限り、エミュレーターのホスト `10.0.2.2` への平文 HTTP を許可する。
- アラームの再登録は、サービスの開始時、再起動時、アプリ更新時に行う(再起動やアプリ更新でアラームが消えるため)。
- `User-Agent` を明示する。Java の既定のままだと、Discord 側で弾かれることがある。

## 結果

得たもの

- サーバーなしで、受け取り側はスマホの Discord だけで済む。
- 端末の電源断や通信不良があっても、期間が欠けずに次回へ持ち越される。

失ったもの

- Webhook URL は端末に平文で保存される。URL を知る人は誰でも投稿できるので、取り扱いに注意が必要である。
- 配信は Discord のサービスと、端末のネットワークに依存する。
- 端末が長時間止まっていると、1 回のサマリの期間が長くなる。

## 検討した代替案

- **メールで送る**: SMTP の認証情報を端末に持つ必要があり、重い。
- **自前のサーバーへ送る**: 運用の負担が増える。
- **`WorkManager` の定期実行**: 時刻の精度が低く、「毎日 23:00」を保証できない。AndroidX も必要になる(→ [0007](0007-no-dependencies.md))。
