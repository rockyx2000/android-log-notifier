# 0008. UI はフラットな道具風にし、ライト / ダークに対応する

- 状態: 採用
- 日付: 2026-10-07

## 背景

最初の画面は標準のボタンを縦に並べただけだった。見た目を整えたところ、角丸のカードと鮮やかなボタンを積む、ありがちな形になり、「AI っぽい」という指摘を受けた。
設定を確かめるための道具なので、装飾より、状態の読みやすさを優先したい。

## 決定

- **カードを使わず、罫線と余白で区切る。** 角丸は 3dp の控えめな値にする。左揃えで配置する。
- **フォント**: 状態・入力欄・ログ・アプリ名は等幅。セクション見出しは、小さく字間を空けた英字のラベル(`TARGETS` / `WEBHOOK` / `CHECKS` / `LOG`)。本文は標準のゴシック。
- **色**: 生成り色の背景に墨色(ダークは逆)。色は、稼働中の緑と、未設定の赤だけにする。「開始」は墨色のベタ塗り、「停止」は枠線のみとする。
- **チェック欄**は、ボタンを並べず、「左に項目名、右に状態」の行にし、タップで該当の設定へ移動する。
- **ダークモード**は、`values-night` の色とテーマで、端末の設定に自動で追従する。アプリ内の切替は持たない。夜用のテーマでは、ステータスバーのアイコンを白にする。
- **システムバー**: targetSdk 36 ではエッジ・トゥ・エッジが強制される。外側のレイアウトにバーの高さ分だけ余白を持たせ、その内側にスクロール領域を置く。これで、内容がバーの下に重ならない。
- ログは、`10-07 14:01:58  A  example.com` の形に整えて表示する(保存形式は変えない)。

## 結果

得たもの

- 状態(稼働中か、設定は足りているか)が、一目で読める。
- 色の定義が `colors.xml` の 6 色に集約され、ライト / ダークの両方を同じ構造で扱える。

失ったもの

- 見た目の好みは分かれる。変えたくなったときは、`colors.xml` と `styles.xml` を直せば済む。
- アプリ内のテーマ切替がない。端末の設定に従う。
- 外部ライブラリがないので([0007](0007-no-dependencies.md))、スタイルは自前で保つ必要がある。

## 検討した代替案

- **Material 3 を導入する**: 見た目は整うが、依存が増え、この用途には過剰である。
- **カード型のまま、色だけ調整する**: 「AI っぽさ」の原因が、形そのものにあるため、解決しない。
