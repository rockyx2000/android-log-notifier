# 0001. DNS だけを横取りするローカル VPN で記録する

- 状態: 採用
- 日付: 2026-10-07

## 背景

「どのドメインにアクセスしたか」を端末単体で記録したい。root 化や外部サーバーは使いたくない。
Android で他アプリの通信先を知る現実的な方法は、`VpnService` で通信を経由させることである。

## 決定

`VpnService` を使い、仮想 DNS サーバー `10.0.0.1` へのルート(`/32`)だけを TUN に向ける。

- `addDnsServer(10.0.0.1)` と `addRoute(10.0.0.1, 32)` により、DNS の問い合わせだけが TUN に入る。DNS 以外の通信は VPN を経由せず、通常どおり流れる。
- TUN から読んだ IPv4 / UDP / 宛先ポート 53 のパケットだけを処理する(`DnsPacket` は質問部だけを読む最小パーサ)。
- 問い合わせは実際の上流 DNS へ転送する。ソケットは `protect()` して VPN を迂回させ、ループを防ぐ。応答は IPv4 / UDP ヘッダで包み直して TUN へ返す。

## 結果

得たもの

- root・外部サーバー不要で、端末内だけで完結する。
- 通信全体を中継しないので、速度への影響と、通信内容に触れるリスクが小さい。

失ったもの

- 見えるのは IPv4 の UDP の DNS だけである。アプリ独自の DoH、TCP の DNS、IPv6 の DNS サーバーへの問い合わせは記録できない。
- 他の VPN アプリを起動すると、この VPN は解除される(→ [0006](0006-detect-and-report-gaps.md) で報告する)。
- Private DNS(DoT)を厳格モードにしている端末では、名前解決が失敗する可能性がある。

## 検討した代替案

- **全通信を中継する VPN**: SNI などからも見られるが、処理が重く、通信内容に触れてしまう。目的に対して過剰なので採らなかった。
- **ルーターや DNS サーバー側で記録する**: 端末単体で完結しなくなり、外出先の通信も見られない。
- **アクセシビリティサービスでブラウザの URL を読む**: 権限が強すぎ、アプリごとの実装に依存する。
