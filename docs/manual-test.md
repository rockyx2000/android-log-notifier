# 手動テスト手順(実機)

自動テストで再現しにくい項目を、リリースの前に実機で確認するための手順です。
方針は [ADR 0010](adr/0010-testing-strategy.md) を参照してください。

> エミュレーターで自動化済みの項目(`./gradlew :app:connectedDebugAndroidTest` と `scripts/e2e.sh`)は、基本動作・強制終了後の復帰・途切れの記録・停止・送信範囲と再試行です。
> この手順書は、**実機でしか確かめられない項目**(省電力・実際のネットワーク切替・再起動・他の VPN・本物の Discord)に集中してください。

準備: 記録対象に、普段使うドメインを 1 つ入れておく(例: `example.com`)。Webhook は、テスト用のチャンネルのものを使う。

## 1. 基本

- [ ] インストールできる(「提供元不明のアプリ」の許可後)
- [ ] 初回起動で、通知の許可と、バッテリー最適化の除外のダイアログが出る
- [ ] 初回起動で、通知の許可 → バッテリー最適化の除外 → VPN の許可の順にダイアログが出て、許可すると自動で「● 記録中」になる(ダイアログが重ならない)
- [ ] 「停止」を押した後、アプリを開き直しても、自動では始まらない。「開始」で戻る
- [ ] ブラウザで対象ドメインを開くと、ログ欄に増える
- [ ] 対象外のドメインを開いても、ログに増えない
- [ ] 保存した記録対象の変更が、アプリの再起動なしで、次の問い合わせから反映される
- [ ] 「テスト送信」で、Discord に直近 24 時間の集計が届く

## 2. 省電力・常駐(Nothing Phone で重点的に)

- [ ] 画面を消して 30 分放置した後、対象ドメインを開くと記録される
- [ ] 一晩放置した翌朝、「● 記録中」のまま、記録が続いている
- [ ] 最近使ったアプリからスワイプで消しても、記録が続く(止まる場合は、アプリのロックを試す)
- [ ] 「アプリの電池設定」を「制限なし」にした場合と、そうでない場合で、止まり方が違うかを記録する
- [ ] バッテリーセーバーをオンにすると、どうなるかを記録する

## 3. ネットワーク

- [ ] Wi-Fi からモバイル回線に切り替えた後も、名前解決でき、記録が続く
- [ ] モバイル回線から Wi-Fi に戻した後も、同様である
- [ ] 機内モードにして解除した後、名前解決が戻る

## 4. 復帰と報告

- [ ] 端末を再起動すると、**ロックを解除する前に** VPN が自動で再開する(通知で確認できる)
- [ ] ロックを解除する前に記録された名前解決が、解除後にログへ反映される
- [ ] 画面ロックを設定した実機で、電源を入れ直し、解除せずに放置してから解除しても、記録に空白が出ない(出た場合は、サマリの途切れの報告と一致するか)
- [ ] 設定 → アプリ → 強制停止した後、アプリを開くと、自動で再開する
- [ ] 上の 2 つの後、次のサマリに「⚠ 記録が途切れた可能性」が出る
- [ ] 他の VPN アプリを起動すると、この VPN が解除され、サマリに「VPN が解除され停止中」と出る
- [ ] ユーザーが「停止」を押した分は、途切れとして出ない

## 5. サマリの送信

- [ ] 23:00 に、サマリが Discord に届く(時刻のずれを記録する)
- [ ] 「正確なアラーム」を許可していない場合の、ずれの大きさを記録する
- [ ] Webhook を壊して送信を失敗させると、「送信失敗」が表示され、15 分後に再試行される
- [ ] 失敗した日の分が、次回のサマリにまとめて載る(取りこぼしがない)
- [ ] 記録が 1 件もない日に、「アクセスはありませんでした」のサマリが届く

## 6. 制限事項の確認(README の「制限事項」と合っているか)

- [ ] ブラウザの「セキュア DNS(DoH)」をオンにすると、記録されない
- [ ] 端末の Private DNS を「自動」にしても、名前解決と記録が動く
- [ ] 端末の Private DNS を「厳格」にした場合の挙動を記録する(名前解決が失敗するか)
