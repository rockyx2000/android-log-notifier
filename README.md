# DNS Logger

指定したドメインへの **DNS 問い合わせ** を端末内で記録し、毎日 23:00 に **Discord** へ集計を送る Android アプリです。

「いつ・どのサイトの名前解決をしたか」を、端末の外に通信内容を出さずに把握することを目的にしています(想定ユースケース: 自分や家族の端末での利用状況の把握)。

> **注意**: 記録できるのは DNS の問い合わせ(FQDN と時刻)だけです。ページの中身や通信内容は見えません。利用者本人または保護者など、**正当な権限のある端末にだけ** 導入してください。

## 設計思想

1. **見るものを最小にする** — 通信全体ではなく、DNS の問い合わせだけを見ます。さらに、設定した FQDN に一致するものしか保存しません。
2. **端末の外に出すものも最小にする** — ログは端末の内部ストレージにだけ置きます。外に出るのは、1 日 1 回の集計(回数と最終時刻)だけです。
3. **黙って止まらない** — 常駐アプリは OS に止められがちです。止まったことを検知し、サマリで報告します。
4. **依存を持たない** — AndroidX もサードパーティのライブラリも使わず、Android 標準 API だけで作っています。小さく、読み切れる量に保つためです。

判断の経緯は [docs/adr](docs/adr/README.md) にあります。

## 仕組み

```
 アプリ ──DNS クエリ──▶ 10.0.0.1 (仮想 DNS) ─┐
   │                                          ▼
   └─ それ以外の通信は VPN を通らず        TUN デバイス
      通常どおり流れる                          │ DnsVpnService が読む
                                                ├─ FQDN を解析 → 指定ドメインなら AccessLog に追記
                                                └─ 実際の上流 DNS へ転送(VPN を迂回)し、応答を TUN へ返す

 23:00 のアラーム ─▶ SummaryReceiver ─ 集計 ─▶ Discord Webhook
```

- `VpnService` で `10.0.0.1/32` だけを TUN にルーティングします。DNS 以外の通信は VPN を経由しません。
- 上流 DNS は、VPN 以外のネットワークから取得します。Wi-Fi とモバイルの切替にも追従します。
- 常駐はフォアグラウンドサービスで行います。生存確認を 60 秒ごとに書き、途切れを検知します。

## 機能

| 機能 | 内容 |
| --- | --- |
| DNS 記録 | 指定 FQDN の問い合わせを `時刻 / FQDN / 種別` で記録。同一 FQDN は 60 秒以内なら 1 回とみなす |
| 日次サマリ | 毎日 23:00 に、前回の送信済み時刻から今回の 23:00 までを集計して Discord へ送信 |
| 取りこぼし補完 | 送信に失敗したら 15 分後に再試行。端末の再起動などで漏れても、前回の終端から集計し直す |
| 途切れ検知 | OS に止められて再開した場合、その空白をサマリに `⚠ 記録が途切れた可能性` として載せる |
| 自動再開 | 端末の再起動・アプリ更新後、およびアプリを開いたときに、「開始」のまま止まっていれば再開 |
| 省電力対策 | バッテリー最適化の除外を案内し、現在の状態を画面に表示 |
| 表示 | ライト / ダークモード対応(端末設定に追従) |

### 記録対象の書式

1 行に 1 つ。カンマ・空白区切りも可、`#` 以降はコメントです。**リストが空なら何も記録しません。**

```
dmm.co.jp          # dmm.co.jp と *.dmm.co.jp(サブドメインも対象)
=www.dmm.co.jp     # 完全一致のみ
```

### サマリの例

```
DNS アクセスサマリ
期間: 10/6 23:00 〜 10/7 23:00
⚠ 記録が途切れた可能性: 1 回 / 計 75 分
  10/7 03:10 〜 10/7 04:25
合計 12 回 / 2 ドメイン
   8回  example.com  (最終 10/7 14:01)
   4回  www.iana.org  (最終 10/7 09:30)
```

## セットアップ

### 必要なもの

- JDK 17(Android Gradle Plugin の要件。JDK 15 以下ではビルドできません)
- Android SDK(`compileSdk 36`)。実行には Android 12(API 31)以上が必要です
- Android 12(API 31)以上の端末またはエミュレーター(Nothing Phone (1) 以降が対象)

### ビルドとインストール

```sh
# SDK の場所を指定(local.properties は Git 管理外)
echo "sdk.dir=/path/to/android/sdk" > local.properties

export JAVA_HOME=/path/to/jdk-17
./gradlew :app:installDebug      # 接続中の端末・エミュレーターに入る
```

### リリース用 APK のビルド

署名つきの APK を作るには、署名鍵を用意し、プロジェクト直下に `keystore.properties` を置きます(Git 管理外)。

```properties
storeFile=/path/to/release.jks
storePassword=...
keyAlias=dnslogger
keyPassword=...
```

```sh
./gradlew :app:assembleRelease      # → app/build/outputs/apk/release/app-release.apk
adb install -r app/build/outputs/apk/release/app-release.apk
```

- `keystore.properties` が無い場合、署名なしの APK になり、そのままではインストールできません。
- **署名鍵は必ずバックアップしてください。** 失うと、同じアプリとして更新できなくなります(再インストールが必要で、設定とログは消えます)。リポジトリには入れません。
- 署名の確認: `apksigner verify --print-certs app-release.apk`

### 初回の設定

1. アプリを開き、通知の許可を与えます。
2. 「バッテリー最適化」の除外ダイアログが出たら許可します。
3. 「TARGETS」に記録したい FQDN を入力します。
4. 「WEBHOOK」に Discord の Webhook URL を入力し、「保存」を押します。
   - Release ビルドでは `https://` で始まる URL だけ受け付けます。
   - 「正確なアラーム」が未許可なら、設定画面が開きます。許可してください。
5. 「テスト送信」で、直近 24 時間の集計が届くことを確認します。
6. 「開始」を押し、VPN 接続の確認ダイアログを許可します。

### Nothing Phone など実機での注意

標準の「バッテリー最適化の除外」だけでは、OS 側の制限が残ることがあります。次も設定してください。

- 設定 → アプリ → DNS Logger → アプリのバッテリー使用量 → **制限なし**(画面の「アプリの電池設定」から開けます)
- 最近使ったアプリ一覧でアプリを **ロック** する
- バッテリーセーバーをオフにする

### エミュレーターでの確認

エミュレーターからホストの PC は `10.0.2.2` で見えます。Debug ビルドに限り、`10.0.2.2` への平文 HTTP を許可しているので、ローカルの受信サーバーに Webhook を向けてテストできます。

## テスト

```sh
./gradlew :app:testDebugUnitTest                              # 層 1: 単体テスト(端末不要・数秒)
./gradlew :app:connectedDebugAndroidTest                      # 層 2: 計装テスト(エミュレーター / 実機が必要)
./gradlew :app:assembleDebug && scripts/e2e.sh                # 層 3: 結合テスト(エミュレーター上で VPN を実際に動かす)
./gradlew :app:lintRelease                                    # リント(エラーが 0 件であること)
```

| 層 | 件数 | 確かめること |
| --- | --- | --- |
| 1. 単体 | 53 | DNS パケットの読み書き、記録対象の判定、23:00 の区切りと送信範囲、サマリ本文 |
| 2. 計装 | 30 | ログの重複抑制とローテーション、途切れの記録、アラーム登録、**送信の経路**(偽の Webhook を端末内に立てる。本物の Discord には送らない) |
| 3. 結合 | 18 項目 | 開始、記録対象の判定、Wi-Fi の切断と再接続、強制終了後の自動再開と途切れの記録、停止 |

- テストは、デバッグ版(`com.github.rockyx2000.dnslogger.debug`)に対して動きます。リリース版とは別のアプリで、データも別です。
- `scripts/e2e.sh` は VPN を使います。同時に VPN になれるのは 1 つだけなので、リリース版が記録中なら解除されます。
- 実機でしか確かめられない項目(省電力・実際のネットワーク切替・再起動・他の VPN)は、[手動テスト手順](docs/manual-test.md)にまとめています。
- 方針は [ADR 0010](docs/adr/0010-testing-strategy.md) を参照してください。

## 制限事項

- **IPv4 の UDP の DNS だけを記録します。** アプリやブラウザが独自に DoH(DNS over HTTPS)を使っている場合は、その問い合わせを見られません。
- 端末の Private DNS(DoT)を厳格モードにしていると、名前解決自体が失敗する可能性があります。自動モードにしてください。
- 記録するのは名前解決であり、実際にアクセスしたかどうかではありません。OS やアプリのキャッシュにより、実際の閲覧回数より少なく数えます。
- 途切れの開始時刻は「最後に生存を確認できた時刻」です。端末のスリープ中は確認が更新されないため、実際に止まった時刻より早めに出ることがあります。
- 他の VPN アプリが起動すると、この VPN は解除されます。解除された場合はサマリで報告しますが、自動では復帰できません。アプリを開いて再開してください。
- 端末の再起動後は、VPN の許可が生きている場合に限り、画面を開かずに自動で再開します。

## ファイル構成

```
app/src/main/java/com/github/rockyx2000/dnslogger/
├─ MainActivity.kt       画面(設定・状態・ログ表示)
├─ DnsVpnService.kt      ローカル VPN。DNS の中継と記録、上流 DNS の追従、生存確認
├─ DnsPacket.kt          DNS メッセージの質問部だけを読む最小パーサ
├─ UdpDns.kt             TUN 上の IPv4 / UDP パケットの読み取りと応答の組み立て
├─ DomainFilter.kt       記録対象 FQDN の判定
├─ AccessLog.kt          TSV での追記、重複の抑制、ローテーション(5MB・1 世代)
├─ Summary.kt            集計と Discord 向け本文の組み立て
├─ SummaryScheduler.kt   23:00 のアラーム登録
├─ SummaryReceiver.kt    アラームで起動し、集計・送信・再試行
├─ DiscordNotifier.kt    Webhook への POST
├─ Health.kt             生存確認と途切れの記録
├─ BootReceiver.kt       再起動・アプリ更新後の再開
└─ Settings.kt           設定と状態の保存(SharedPreferences)

app/src/test/            単体テスト(層 1)
app/src/androidTest/     計装テスト(層 2)
scripts/e2e.sh           結合テスト(層 3)
docs/                    ADR(設計判断)と手動テスト手順
```
